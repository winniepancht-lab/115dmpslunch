# 東門國小家長會・營養午餐試菜系統 v3

三種角色、三個入口：

| 角色 | 入口 | 能做什麼 |
|---|---|---|
| 一般家長（公開） | `index.html`、`week.html` | 只看去識別化內容：年級代表、照片、已核可的紀錄與議題 |
| 輪值家代 | `rep.html?t=個人連結` | 只能填「自己輪值日」的試菜心得與照片，送出後待幹部審核；沒有議題／意見欄位 |
| 幹部 | `admin.html`（通關密語） | 審核、補登、議題、班表、統計、查詢比對 |

## 一、為什麼更安全
- 試算表**不再發布到網路**，前台改讀 Apps Script 的「公開資料」介面，那裡只輸出已上線資料的年級、文字、照片，**沒有姓名、班級、填報時間**。
- 家代以個人連結（32 碼隨機 token）填寫，伺服器會檢查「這位家代今天是否輪值」；沒有班表就不能送出。
- 幹部操作都要通關密語；任何人無法直接編輯或下載後台資料。
- 家代送出 → 待審 → 幹部核可才公開。幹部補登可「一次上線」。

## 二、設定步驟（依序做，一次）
1. **停止舊的公開**：試算表 → 檔案 → 共用 → 發布到網路 → **停止發布**（v2 的 CSV 連結會失效，這是預期的）。確認試算表一般存取權是「限制」。
2. **Apps Script**：把 `Google_Apps_Script.js` 全部貼上取代 → 儲存 → 部署 → 管理部署作業 → 鉛筆 → 版本「新版本」→ 部署。網址與 `KEY` 都不變，`js/config.js` 不用改。
   首次若要求授權請同意。新分頁（紀錄、議題、班表、家代名冊、菜單）會自動建立。
3. **上傳網站**：整個資料夾覆蓋上傳 GitHub Pages。
4. **登入後台** `你的網站/admin.html`：
   - 「班表與設定」→ **匯入 v2 舊資料**（把 9 月起的紀錄與議題搬進 v3）。
   - 「班表與設定」→ 選輪值表與名冊 xlsx → **解析並匯入**（姓名只存在私有試算表）。
   - 在「家代個人填寫連結」逐位按「複製邀請訊息」，用 LINE 傳給該位家代。
5. 自己用一個家代連結試填一筆，到後台核可，再開前台確認。

## 三、每天怎麼用
- **家代**：輪值當天開自己的連結 → 貼心得、選照片 → 送出。輪值後 2 天內可補填；被退回會顯示原因，修改後再送出。
- **幹部**：開後台「待審核」→ 檢查文字與照片（可改字、移除照片）→ 核可，或「全部核可上線」。
- **補登**：「補登」可單筆；也可貼 LINE 文字批次補登，系統依班表自動對應家代，確認後一次上線。
- **議題**：在「議題」新增／回覆／結案，可附照片；回覆留空 = 追蹤中。
- **統計與比對**：「家代統計」看每位試菜次數與日期、缺填、還沒試菜；「每日輪值對照」逐日看誰填了；可匯出 CSV。
- **下架／刪除**：「紀錄查詢」找到該筆 → 下架（可再上線）或刪除（照片丟垃圾桶）。

## 四、教育局菜單
後台「班表與設定」有「教育局菜單 API 測試」。把測試結果貼給開發者，即可完成自動帶入每日菜單。
在此之前，「補登」的「當日菜色」欄位可手動填，前台會顯示。

## 五、請留意
- 照片存在你的雲端硬碟「東門試菜照片」，為「知道連結者可檢視」；連結只存在私有試算表與後台，不會出現在公開資料，但**審核前的照片網址仍可被知道網址的人開啟**，請務必在審核時檢查人臉與名牌。退回／刪除會把照片丟垃圾桶。
- 個人連結等同密碼，請勿轉傳；外流時在後台「重產」。
- 名冊只匯入「年級、班級、家長姓名」，不含學生姓名。
- 同姓名的兩位家代會被視為同一人，請避免。
- 通關密語只給幹部，定期更換（Script 屬性 `KEY`）。
